## September 24, 2026: fixed-candidate participant EFA recovery

Independent saved-evidence review accepted the participant-command sequence on two PCS g7.48xlarge nodes: active EFA reset, failed workload, supported recovery refusing a retained warning, exact-target replacement, fresh collective/storage verification and participant result retrieval. The fixed companion and suite candidates were installed before the trial and remained unchanged during it. This is development-candidate evidence, not a claim that these fixes are merged into upstream main. EventEngine personal entry and a first-time 60-minute human rehearsal remain unverified.

The EFA reset recorded authorization, start and return during live communication. The failed 16-rank workload reported watchdog timeouts on every rank and explicit correctness-mismatch exceptions on several ranks. Zero-mismatch progress before failure does not make the whole faulted job correct. The corrected kernel collector retrieved the selected last 512 matching records from the recorded fault boot, including EFA reset/admin/deallocation errors; it did not capture the complete kernel journal.

Supported participant recovery rebooted the original target, but Check 6 retained six cumulative retransmission timeout events. Without a recorded baseline establishing that warning was already present, qualification stopped and the participant used replacement. Pending calls continued the same replacement and bootstrap request. Terminal bootstrap success, fresh successor checks 0/2/3/6, admission and runtime readiness were verified separately. No ad-hoc candidate edits or administrative rescue were observed in the saved trial commands.

The fresh two-node allocation completed in 51 seconds, including 6 seconds of cold container preparation. Its raw results contained all 25 main rows and one separate EFA-only isolation row, all 16 GPU rank headers across two MPI processes, zero in-place/out-of-place mismatches and zero out-of-bounds values. All four physical EFAs had positive receive/transmit/write deltas. The 16-rank storage fixture completed with zero mismatches, and the participant retrieved a digest-matching bundle from the compute nodes into the login account. The provider/performance warning remained, as did later retransmission-byte deltas. This result establishes exercised correctness and retrieval, not a performance target or a warning-free interval.

Measured wall-clock time was 39 minutes 10 seconds from the frozen trial start through retrieval, 35 minutes 9 seconds from the EFA workload allocation through retrieval, and 32 minutes 39.111 seconds from fault start to runtime readiness. The fixed bootstrap reported 451.637 seconds. These intervals include machine waits and must remain in workshop budgeting; none is a timed human rehearsal. An unapproved 60-minute proposal assigns one live branch per table and compares other mechanisms during waits. Device tables read recorded storage and DataLoader outcomes; storage tables execute those controls and compare device records. Both routes then discuss correctness coverage and complete the runbook. Full additional branches remain available for separately scheduled practice; content-owner agreement and human rehearsal remain open.

### GPU and storage evidence remain distinct

The September 24 participant GPU attempt recorded authorization and reset start but no return. An unexpected target reboot preceded participant recovery; only the eight peer ranks emitted watchdogs in the retained workload log. The older kernel collector failed, so neither reset completion nor the initial reboot cause is established. Participant recovery restored the same instance and a fresh collective/storage job plus participant retrieval passed. The later kernel correction, verified during the EFA fault boot, does not repair that historical missing GPU capture.

A separate September 23 administrator GPU trial recorded reset start and return and watchdogs on all 16 ranks, followed by cleanup stalling until the six-minute allocation limit. Watchdog detection and later scheduler termination are separate events. This evidence cannot be substituted for the participant GPU attempt. Neither trial establishes physical PCIe loss, Xid 79 or silent data corruption.

The September 16 storage logs already contain NCCL INFO initialization from all 16 ranks, writer ENOSPC/retries and a real 30-second ProcessGroupNCCL watchdog. The isolated 32 MiB fixture's retry policy keeps the writer out of the next collective for up to 60 seconds. Injection, recovery and cleanup wrappers took 112, 22 and 5 seconds respectively. Writer lines lack timestamps, so exact ENOSPC onset is unknown. Recovery resumed the retained next-step index and completed with zero mismatches; it did not recover a model/optimizer checkpoint or reproduce an FSx service outage.
